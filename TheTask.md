# ТЗ: Приложение для организации практики студентов на кафедре

Учебный проект. Бюджет времени — ~30 часов. Приоритет — рабочий сквозной сценарий, а не полнота фич.

## 1. Назначение

Приложение автоматизирует организацию производственной практики студентов кафедры:
принимает данные из Excel-документов, которые кафедра готовит вручную, позволяет
**вручную распределить студентов по организациям**, и генерирует итоговые .docx-документы
по этому распределению.

Распределение студентов по организациям — центральная функция приложения, а не побочный
эффект импорта. Кафедра сама решает, кого куда направить; система хранит и валидирует это
решение, но не предлагает вариантов автоматически.

## 2. Входные данные (Excel, 4 вида)

| Файл | Колонки | Создаёт в БД |
|---|---|---|
| Список студентов | ФИО, группа | `Student` |
| Список организаций | Название, адрес | `Organization` |
| Список руководителей | ФИО, организация, должность | `Supervisor` (FK на `Organization`) |
| Список практик | Тип, дата начала, дата конца, группа | `Practice` |

Импорт — get-or-create по каждой строке, без preview/подтверждения, дубли допустимы
(не тратим время на валидацию входных данных — проще подогнать тестовые файлы под парсер).

Группа хранится строкой в `Student` и `Practice`, отдельной таблицы `Group` нет — это
осознанное упрощение (группа нигде не выступает самостоятельным объектом со своими
атрибутами, используется только как фильтр).

## 3. Распределение студентов (ядро функционала)

Ручное распределение через API: кафедра явно создаёт запись — студент направляется
к конкретному руководителю в конкретной организации в рамках конкретной практики.

- `POST /assignments` — создать распределение: `student_id`, `organization_id`,
  `supervisor_id`, `practice_id`
- `GET /assignments?practice_id=` — посмотреть текущее распределение по практике
  (нужно, чтобы видеть, кто уже распределён, прежде чем распределять оставшихся)
- `DELETE /assignments/{id}` — отменить/скорректировать распределение

Оценка (`grade`) на этом этапе ещё не проставляется — она приходит позже, отдельным шагом,
через ведомость.

## 4. Ведомости — простановка оценки к уже распределённым студентам

Ведомость обновляет `grade` у **существующего** `Assignment`, найденного по связке
студент + организация. Если на момент импорта ведомости соответствующего `Assignment`
ещё нет (студент не был распределён) — строка ведомости пропускается
(фиксируется в ответе как отклонённая, не бросает ошибку всего импорта).

- `POST /import/gradesheets` — колонки: ФИО, Организация, Оценка

Отсюда следует жёсткий порядок: **распределение обязано случиться раньше ведомостей.**

## 5. Выходные документы (.docx, 3 вида)

| Документ | Гранулярность | Логика |
|---|---|---|
| **Направление** | Пакетно по практике | Один .docx со всеми направлениями студентов данной практики, разделены page break'ом |
| **Приказ** | По практике | Один .docx с пронумерованным списком всех распределённых студентов практики |
| **Сводный отчёт** | За год | Агрегат по всем практикам и группам за указанный год |

Направление и приказ строятся по одной и той же выборке (`Assignment` по `practice_id`) —
выборка вынесена в общий helper.

## 6. Модель данных

```
Student(id, full_name, group)
Organization(id, name, address)
Supervisor(id, full_name, position, organization_id)
Practice(id, type, date_start, date_end, group)
Assignment(id, student_id, organization_id, supervisor_id, practice_id, grade)
```

`grade` — nullable до прихода ведомости.

## 7. Стек

- **FastAPI** — веб-фреймворк, Swagger (`/docs`) как интерфейс тестирования, без отдельного фронта
- **SQLite** — БД, без отдельного сервиса
- **SQLAlchemy** (sync) — ORM, без Alembic (пересоздание через `Base.metadata.create_all()`)
- **pandas + openpyxl** — парсинг Excel
- **docxtpl** — генерация .docx по Jinja2-шаблонам
- Без Celery/Redis, без сложной авторизации, без ролей

## 8. Слои приложения

```
app/
├── api/            # роутеры
├── schemas/        # Pydantic-модели запросов/ответов
├── services/        # бизнес-логика (импорт, распределение, отчёты)
├── repositories/     # CRUD через SQLAlchemy
├── models/         # ORM-модели
├── documents/        # docxtpl-генерация
├── db/             # сессия, инициализация SQLite
└── core/           # конфиг, .env
```

Поток: `Router → Service → Repository → DB`; для документов: `Service → documents/generator → файл`.

## 9. Полный список эндпоинтов (10 шт.)

```
POST   /import/students
POST   /import/organizations
POST   /import/supervisors
POST   /import/practices

POST   /assignments
GET    /assignments?practice_id=
DELETE /assignments/{id}

POST   /import/gradesheets

GET    /documents/directions?practice_id=
GET    /documents/order/{practice_id}
GET    /documents/report?year=
```

## 10. Сценарий использования

1. Загрузить студентов, практики, организации, руководителей (Excel) — в любом порядке
2. Распределить студентов по организациям вручную через `POST /assignments`
   (по одному на каждую пару студент–организация; список текущего распределения — через `GET /assignments?practice_id=`)
3. Загрузить ведомость — проставляет `grade` уже распределённым студентам
4. Получить направления по практике, приказ по практике, отчёт за год

## 11. Явно вне рамок проекта

- LLM-фича (автоматическая рекомендация распределения) — не входит в ТЗ-минимум
- Отдельная сущность/таблица `Group`
- Preview/подтверждение импорта, upsert по естественным ключам
- Роли и авторизация
- Очереди/асинхронная генерация документов
- `PATCH /assignments/{id}/grade` — оценка меняется только через повторный импорт ведомости
